# Test Plan for tensaiGPT

**Seed:** tests/seed.spec.ts

---

## 1. Authentication & Login

### 1.1 SSO Login Flow
**Steps:**
1. Navigate to https://tensaigptnew-qa.tensai.run/
2. Verify "Welcome to tensaiGPT" heading is displayed
3. Verify tagline "SMARTER CHATS BRIGHTER IDEAS" is visible
4. Click "SSO Login" button
5. Verify redirect to Microsoft login page (login.microsoftonline.com)
6. Verify "Sign in" heading on Microsoft login page
7. Verify email/phone input field is active and visible

**Expected:**
- SSO Login button is clickable and functional
- User is redirected to Microsoft OAuth2 authentication endpoint
- Microsoft login form displays correctly with email input field
- Login URL contains correct client_id and redirect_uri parameters

### 1.2 Microsoft Login Form Validation
**Steps:**
1. On Microsoft login page, verify email input field placeholder text "Email, phone, or Skype"
2. Verify "Next" button is available
3. Verify "Can't access your account?" recovery link is present
4. Verify "Sign-in options" button is available
5. Verify footer links (Terms of use, Privacy & cookies) are visible

**Expected:**
- All form elements render correctly
- Footer contains valid links to Microsoft's Terms and Privacy pages
- Help/troubleshooting button is accessible

## 2. Chat Functionality

### 2.1 Chat Interface Launch
**Steps:**
1. Complete SSO authentication successfully
2. Verify user is redirected back to https://tensaigptnew-qa.tensai.run/
3. Verify chat interface loads
4. Verify main chat window is displayed and ready for input

**Expected:**
- Dashboard/chat interface loads after successful authentication
- Chat input area is visible and active
- Previous conversations (if any) are displayed

### 2.2 Send Message
**Steps:**
1. Click on chat message input field
2. Type a test message (e.g., "Hello tensaiGPT")
3. Press Enter or click Send button
4. Wait for response

**Expected:**
- Message appears in chat window with user attribution
- System processes message and returns response
- Response displays with agent attribution
- Chat history is preserved

### 2.3 Multi-turn Conversation
**Steps:**
1. Send initial message
2. Receive response
3. Send follow-up message related to previous context
4. Receive contextual response

**Expected:**
- Agent maintains conversation context
- Follow-up messages reference previous exchanges appropriately
- No loss of conversation history

## 3. Agent Selection

### 3.1 Agent Availability
**Steps:**
1. After successful login, locate agent selection interface
2. Verify list of available agents is displayed
3. Identify agent names and descriptions

**Expected:**
- All available agents are listed
- Agent descriptions are clear and informative
- Default agent is pre-selected (if applicable)

### 3.2 Agent Switching
**Steps:**
1. Select different agent from available list
2. Verify agent selection changes
3. Send message to new agent
4. Verify message is routed to correct agent

**Expected:**
- Agent selection updates immediately
- Chat interface reflects selected agent
- Messages are processed by selected agent
- Agent-specific behavior/responses are evident

### 3.3 Agent Context Preservation
**Steps:**
1. Start conversation with Agent A
2. Switch to Agent B mid-conversation
3. Verify if Agent B can access previous conversation context

**Expected:**
- Clear indication of whether context is preserved or reset
- Behavior is consistent with product design
- User receives appropriate guidance on context availability

## 4. File Upload Functionality

### 4.1 Upload Interface
**Steps:**
1. In active chat, locate file upload option
2. Verify upload button/area is visible and accessible
3. Click to open file browser

**Expected:**
- File upload control is clearly visible
- File browser dialog opens when triggered
- Upload area supports drag-and-drop (if designed)

### 4.2 File Upload - Supported Types
**Steps:**
1. Attempt to upload supported file type (PDF, DOCX, TXT, etc.)
2. Monitor upload progress
3. Wait for upload completion
4. Verify file appears in chat context

**Expected:**
- File uploads successfully
- Progress indicator shows upload status
- File is attached to current chat session
- File name/reference is visible in chat

### 4.3 File Upload - Unsupported Types
**Steps:**
1. Attempt to upload unsupported file type (EXE, BAT, etc.)
2. Observe system response

**Expected:**
- System rejects file with clear error message
- Error message indicates supported file types
- No malicious files are accepted

### 4.4 File Size Limits
**Steps:**
1. Prepare test file exceeding likely file size limit
2. Attempt to upload large file
3. Observe system response

**Expected:**
- System enforces file size limits with clear messaging
- User is informed of maximum allowed size
- Upload is prevented before processing

### 4.5 Multiple File Upload
**Steps:**
1. Upload first file successfully
2. Upload second file in same chat session
3. Verify both files are referenced in chat context
4. Send message referencing both files

**Expected:**
- Multiple files can be uploaded sequentially
- All files remain accessible in chat session
- Agent can reference and process multiple files

### 4.6 File Processing in Messages
**Steps:**
1. Upload document (e.g., PDF)
2. Send message asking agent to analyze/summarize file
3. Agent should reference file content in response

**Expected:**
- Agent accesses and processes uploaded file
- Response demonstrates file content comprehension
- File context is integrated into agent responses

## 5. Error Handling & Edge Cases

### 5.1 Session Timeout
**Steps:**
1. Authenticate and access chat interface
2. Wait for extended period without interaction
3. Attempt to send message

**Expected:**
- Clear indication if session has expired
- User is prompted to re-authenticate if needed
- No data loss on chat history

### 5.2 Network Interruption
**Steps:**
1. During message send, simulate network disconnection
2. Observe system behavior
3. Restore connection
4. Attempt to resend message

**Expected:**
- Clear error indication when network fails
- Graceful handling without application crash
- Message retry mechanism available

### 5.3 Invalid Authentication Token
**Steps:**
1. Successfully authenticate
2. Manually corrupt/delete authentication token
3. Attempt to send message

**Expected:**
- System detects invalid token
- User is redirected to login
- Clear error message is displayed

## 6. UI/UX Validation

### 6.1 Responsive Design
**Steps:**
1. Access application on desktop browser
2. Resize browser window to tablet size
3. Resize browser window to mobile size
4. Verify functionality on each breakpoint

**Expected:**
- Layout adapts appropriately
- All controls remain accessible
- No horizontal scrolling on mobile
- Touch targets are adequate size

### 6.2 Accessibility
**Steps:**
1. Navigate using keyboard only (Tab, Enter, Arrow keys)
2. Test with screen reader (NVDA/JAWS)
3. Verify color contrast meets WCAG standards

**Expected:**
- All interactive elements are keyboard accessible
- Screen reader provides meaningful labels
- Color contrast is adequate for readability

### 6.3 Performance
**Steps:**
1. Measure initial page load time
2. Measure time to first message response
3. Monitor for memory leaks during extended use
4. Test with slow network (3G simulation)

**Expected:**
- Page loads within acceptable time (<3s)
- First response received in reasonable time (<5s)
- No performance degradation over extended use
- Application functions on slower connections

3. Check for secure storage indicators

**Expected:**
- Messages transmitted via HTTPS
- No sensitive data logged to console
- Appropriate security headers present

### 7.2 Authentication Token Security
**Steps:**
1. Authenticate successfully
2. Inspect network traffic and storage
3. Verify token is stored securely

**Expected:**
- Tokens are HttpOnly (not accessible via JavaScript)
4. Tokens use Secure flag for HTTPS only
